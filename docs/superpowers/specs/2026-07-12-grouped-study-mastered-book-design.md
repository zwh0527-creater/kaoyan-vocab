# 考研单词：20 词分组、英语一搭配与熟词本设计

日期：2026-07-12
状态：功能与视觉方向均已由用户批准

## 1. 目标与边界

在现有离线 PWA 上完成一次学习体验改版：每天仍最多学习 300 词，但拆成最多 15 组，每组最多 20 词；增加面向考研英语一的简短固定搭配；把学习判断改为“只标熟词”，未标熟词继续进入下一轮。

首版继续保持个人、离线、零付费服务，不加入搜索、例句、拼写测试、提醒、统计、打卡、排行榜、云同步或 App Store 发布。

现有基础词库保持 5493 条、原 PDF 顺序和现有词库指纹。搭配数据独立维护，不改变基础词库指纹，避免词组更新导致旧进度和备份失效。

## 2. 已选方案与取舍

### 2.1 学习循环

采用“整轮走完后再复习未掌握词”的方案：

- 一天最多取当前轮中尚未见过的 300 词。
- 这些词分成 15 个 20 词小组。
- 明确标为熟词的词退出学习池。
- 所有未标熟词按原相对顺序进入下一轮等待队列。
- 当前轮的全部词走完后，才开始下一轮。

不采用“未标熟词第二天立刻重学”，因为它会挤占第二天接触新词的空间，也会破坏先快速走完整张词表的方法。不采用按遗忘曲线自动排期，因为这会把首版扩成另一套学习系统。

例如：第 1 天学习 300 词，只标了 15 个熟词，那么 285 词进入第 2 轮等待队列。第 2 天仍学习第 1 轮后面的 300 个新词。等 5493 词全部完成第 1 轮后，第 2 轮才从所有未标熟词开始。

### 2.2 熟词恢复

采用逐词恢复：熟词本中的每个词单独提供“重新学习”，点击后只有该词离开熟词本，进入下一轮等待队列。

不提供“全部重新学习”“清空熟词本”或批量选择，也不把恢复的词立即插入当天正在学习的 20 词小组。这样不会因为一次误操作推翻用户已经确认的掌握判断。

### 2.3 词组内容

采用静态、构建时整理的词组数据：每个词最多展示 1–3 个可靠的固定搭配或词组及简短中文释义。红宝书用于判断考研相关性和内容层级，ECDICT 等许可明确的词典数据用于校验和补充。界面使用“考研常见搭配”等准确表述；只有能核实来自英语一真题的内容才可标为“真题”。

不在运行时请求第三方接口，不复制红宝书扫描页、长例句、记忆口诀或整段解析，也不为凑数量编造词组。没有可靠搭配时，详解页只展示基础释义，并明确显示“暂未收录可靠搭配”。

## 3. 用户流程

### 3.1 首页

首页保留 App 名称和当前轮次，今日进度改为同时显示：

- 已完成组数 / 今日总组数，例如 `6 / 15 组`；
- 已完成词数 / 今日总词数，例如 `120 / 300 词`；
- 当前轮剩余词数；
- 下一轮等待词数。

主按钮根据状态显示“开始第 1 组”“继续第 7 组”或“今天已完成”。首页增加“熟词本”入口和熟词数量，但不增加额外统计图表。

### 3.2 学习页

学习页一次只渲染当前小组，最多 20 词，不再显示 300 词长列表。页头显示当前轮次、今日第几组以及本组进度。

每个词条包含：

- 英文、音标和发音按钮；
- 默认隐藏的中文释义；
- “熟词”状态按钮；
- “详解”按钮。

点击词条主体只切换中文释义，不改变熟悉状态。点击“熟词”后按钮变为“已熟”，再次点击可以撤销。只有完成当前小组时仍处于“已熟”的词，才正式移入熟词本；其余词全部进入下一轮等待队列。

“详解”以底部面板打开，展示原词义和 1–3 个考研英语一相关搭配及中文释义，不展示例句、长篇词源或记忆法。关闭面板后回到原学习位置。

词条滚过阅读位置后计入本组已看数量。本组所有词均已看后，启用“完成本组”。完成后先显示简短组结算：本组 20 词、标熟数量、继续下一组按钮。最后一组可以少于 20 词。

### 3.3 当天结束与下一轮

完成当天全部小组后显示日结算：今日完成组数、学习词数、标熟数量和当前轮剩余词数。

当前轮最后一天不足 300 词时，只生成实际需要的小组，不从下一轮补词。当前轮完成后，当天停在结算页；即使同一天重新打开 App，也不开始下一轮。下一轮在下一个手机本地日期开始，避免同一天混入两个轮次。

当下一轮等待队列为空时显示“全部过完”。从熟词本恢复任一词后，完成状态解除，该词在后续新一轮中重新出现。

### 3.4 熟词本

熟词本是低频使用的简洁页面，按基础词库原顺序展示：

- 英文；
- 中文释义；
- 单词级“重新学习”按钮。

不展示音标、发音、词组、详解、统计、搜索、筛选或批量操作。点击某个词的“重新学习”后，只移动该词；其他熟词保持不变。恢复的词不会打断当前组或当天批次，而是按基础词库原顺序插入下一轮等待队列。恢复后该词继续参与每一轮，直到用户再次明确标为熟词。

## 4. 分组与跨天规则

`DAY_LIMIT = 300`，`GROUP_SIZE = 20`。今日总组数为 `ceil(dailyBatch.length / 20)`，最大 15。

小组是最小结算单位：

- 完成一个小组时，熟词移入熟词本，未标熟词进入下一轮等待队列。
- 同一天退出 App 后，再打开时恢复当前小组、已看位置和临时熟词标记。
- 跨午夜时，已经完成的小组保持结算结果。
- 尚未完成的小组从该组第 1 词重新开始，最多重复看 19 词；该组内已经点过的临时“已熟”标记保留。
- 未开始的小组继续保留，再从当前轮队列补足，使新一天最多仍为 300 词。

示例：当天完整完成 6 组并在第 7 组看到第 13 词后跨天。前 6 组已经结算；第 7 组的 20 词从头显示，后续未开始词保留，再补入 120 个当前轮新词，使新一天仍最多 300 词。

## 5. 数据设计

### 5.1 搭配数据

搭配数据与 `words.json` 分离，采用以下逻辑结构：

```ts
interface CollocationEntry {
  phrase: string
  meaning: string
  relevance: 'english-1' | 'postgraduate' | 'general'
}

interface WordDetailEntry {
  wordId: number
  collocations: CollocationEntry[]
}
```

生成时必须验证：

- `wordId` 存在且每个词最多一条详解记录；
- 每个词组和中文释义均非空；
- 每个词最多 3 个词组，去除完全重复内容；
- 数据保持基础词库原顺序；
- 记录独立的数据版本和指纹；
- 构建产物不包含原 PDF 或 OCR 中间扫描图。

### 5.2 学习状态 V2

V2 继续以词条 ID 保存进度，核心字段包括：

```ts
interface StudyStateV2 {
  schemaVersion: 2
  corpusFingerprint: string
  round: number
  currentQueue: number[]
  nextRoundQueue: number[]
  sessionDate: string
  dailyBatch: number[]
  completedGroups: number
  groupSeenCount: number
  groupScrollIndex: number
  pendingMasteredIds: number[]
  masteredIds: number[]
  completedToday: boolean
  allCompleted: boolean
  lastSummary: StudySummaryV2 | null
}
```

`pendingMasteredIds` 只保存尚未完成小组中的临时选择；小组完成后，相应 ID 才移入 `masteredIds`。`allCompleted` 仅表示当前没有任何待学词，不代表某个单词的熟悉状态。所有 ID 队列去重并按基础词库原相对顺序维护。同一个 ID 不得同时存在于熟词本和活动学习队列中。

每次切换熟词、完成小组、退出页面、跨天结算、恢复熟词、导入备份或重置时都保存状态。

## 6. V1 迁移与备份

现有本地 V1 进度和 V1 备份必须可迁移，迁移遵循“宁可多学一次，也不能擅自认定已经掌握”：

- `masteredIds` 初始为空，旧版任何状态都不会自动变成熟词。
- 旧版已经留下的不熟词继续保留在学习池。
- 旧版按原规则被当作“熟悉并退出”的未标记词，重新加入下一轮等待队列。
- 旧版当天进度以完整 20 词组为边界结算；不完整的一组从组首重新学习。
- 旧版“不熟”标记不再作为界面状态，但对应词不会丢失。
- 所有迁移后的队列按原词表顺序去重。

新备份格式升级为 V2，包含完整状态和基础词库指纹。导入 V1 时先迁移再校验；导入 V2 时直接校验。错误版本、损坏 JSON、非法 ID 或其他词库指纹必须拒绝，并且不得覆盖当前进度。搭配数据指纹不参与学习备份兼容判断。

“重新开始”仍需两次确认并先提示导出备份；该操作清空学习进度和熟词本。熟词本页面本身不提供任何整本清空或整本恢复入口。

## 7. 视觉与可用性

视觉方向采用“编辑部词典感”：借鉴优秀生成式设计先建立明确美术方向、再统一细节的做法，不照搬任何现成产品界面。整体应像一本经过现代排版的考研词汇书，耐看、安静，适合每天连续学习。

基础视觉规则：

- 主背景使用暖象牙纸色，正文使用偏暖墨黑，暗红只用于进度、熟词状态和关键动作。
- 英文词头使用本机可用的经典衬线字体，中文解释与操作文字使用系统无衬线字体；不加载网络字体，保证离线一致性。
- 单词是页面唯一主角。学习页使用单栏连续排版，主要依靠留白、字体、对齐和细分隔线组织内容，不把每个词做成悬浮卡片。
- 每条词目提供明显大于旧版的上下留白，英文、音标、隐藏释义和操作区形成稳定阅读节奏。
- 可使用小号组号和词序号辅助定位，但不加入装饰性插画、渐变光晕、玻璃效果、表情符号或无意义图标。
- “熟词”保持轻量描边状态；选中后使用浅暗红底色和“已熟”文字，不用强烈动画。
- “详解”作为次级文字动作；底部面板延续纸面颜色和细线层级，词头醒目，搭配按清晰列表排列。
- 页面过渡和释义展开只使用短促淡入；开启减少动态效果时完全取消非必要动画。

首页、组结算、日结算和熟词本沿用同一套字体、颜色和分隔规则。首页突出今日组数和继续学习，熟词本保持朴素长列表，不另做一套视觉语言。

继续支持深色模式、减少动态效果、至少 44px 触控区域、iPhone 安全区和 320px–430px 宽度。底部详解面板必须可滚动、可由明确关闭按钮退出，并正确管理焦点。熟词本即使接近 5493 词也不能导致明显卡顿，应采用分段渲染或等效的轻量方案，但界面仍表现为一张连续列表。

## 8. 离线与更新

页面、图标、基础词库和完整搭配数据都加入 PWA 离线缓存。缺少某个词的搭配数据或详解数据解析失败时，只隐藏该词的搭配部分，不阻断学习、标熟和保存。

继续使用系统 `speechSynthesis` 作为零网络依赖的发音能力，发音失败只显示轻提示。Service Worker 更新下载完成后，仅在首页提示用户应用，不在学习途中强制刷新。

## 9. 验收测试

### 9.1 状态机

- 首次进入生成 300 词、15 组，每组 20 词。
- 最后一批不足 300 时生成实际组数，最后一组允许少于 20 词。
- 一天 300 词只标 15 个熟词后，285 词进入下一轮等待队列；第二天仍取当前轮后续 300 个新词。
- 当前轮未完成时，下一轮等待词绝不混入当天批次。
- 当前轮全部完成后，下一轮只包含未标熟词和用户从熟词本恢复的词。
- 熟词按钮在小组完成前可撤销，撤销后的词进入下一轮。
- 同日退出恢复当前小组位置；跨天时只重复未完成的当前小组。
- 从熟词本恢复一个词时，只移动该词，不改变其他熟词，也不插入当前小组。
- 全部完成后恢复一个熟词，会创建后续学习轮次。

### 9.2 数据与迁移

- 基础词库仍恰好为 5493 条，原指纹不变。
- 每条搭配记录通过 ID、非空、去重、数量和顺序校验。
- 抽查 PDF 第 1、2、3、中间和末页的基础词条不受改版影响。
- V1 本地进度和 V1 备份迁移后没有任何自动熟词，旧进度中的词不丢失。
- V2 备份导出、清空、导入后，轮次、小组位置、临时标熟和熟词本完全恢复。
- 错误版本、损坏文件、非法 ID 或其他词库备份被拒绝，现有状态不变。

### 9.3 页面与离线

- iPhone Safari 和主屏幕模式下，320px、375px、390px、430px 宽度无横向溢出。
- 学习页只渲染当前 20 词，滚动、展开释义和打开详解流畅。
- 熟词本接近满词库时仍可流畅滚动和逐词恢复。
- 飞行模式下首页、学习、详解、分组结算、熟词本、备份保存均正常。
- 发音失败和缺少搭配只显示轻提示，不影响进度。
- 已下载的新版本不会在学习途中自动刷新。

代码、自动化测试、生产构建和移动端浏览器检查全部通过；旧进度可安全迁移；发布后的 GitHub Pages 在线和飞行模式均可用。README 的现有线上地址与来源说明保留，并补充新学习规则和熟词本说明。
